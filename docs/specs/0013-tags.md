# Spec 0013 — Session tags (Finder-style colored marker on a session)

* Status: **Implemented** — ships in 1.4.0 alongside Bookmarks (spec 0012)
* Date: 2026-07-03

## Why

Sessions in the dropdown are distinguished only by their *live state*
(🟡 active / 🟢 fresh / 🔵 acknowledged / ⚪ stale — `RenderGroup`,
`core.py:1232`). There's no way to mark a session with *your own*
meaning — "this one's the release branch", "this one's the flaky-test
dig", "park this for later". macOS Finder solves the same problem with
**tags**: a small colored dot you slap on a file. This spec borrows that
idea and its palette verbatim.

**Tags** let the user put a single colored **marker** on any session.
It shows up **right after the state circle** in the session row, and —
because Bookmarks (spec 0012) reuse the same row renderer — it shows up
on a bookmarked session's row too, for free.

A tag is a pointer, exactly like a bookmark: the sidecar stores only
`sid + color`, the row is rebuilt from the transcript every tick. Nothing
about a tag freezes session state.

## Product decisions (locked with the user)

1. **One color per session.** Not Finder's multi-tag model — a session
   carries at most one color. Choosing a new color replaces the old one.
   The row shows exactly one tag glyph.
2. **Toggle to clear.** Re-selecting the currently-assigned color removes
   it (the item is `checked` and clicking it clears). There is **no**
   separate "No tag" item.
3. **Seven colors**, in Finder's order: Red, Orange, Yellow, Green, Blue,
   Purple, and **White** (Finder's seventh slot is gray, but gray reads as a
   dead/disabled colour in a menu, so this uses white).
4. **The glyph is an ANSI-coloured circled letter** — `ⓡ ⓞ ⓨ ⓖ ⓑ ⓟ ⓦ`, the
   letter mirroring the colour (`ⓑ` = blue), echoing the model badges
   (`ⓞⓢⓗⓕ`). *Originally* speced as a tinted `flag.fill` SF Symbol, then emoji
   squares, but: SwiftBar does **not** tint SF Symbols in the dropdown
   (`sfcolor` — hex *and* named `system*` — renders them gray, confirmed even on
   the shipping Delete/Remind icons), and emoji squares looked heavy. **ANSI**
   text colour *does* render in the dropdown (it's how the row labels colour),
   so the colour rides in the letter's ANSI escape. See *Rendering the tag*.

## What the user does

* **Assign / clear a tag** — every session's submenu gets a **Tags ▸**
  parent item, placed right after *Reveal in Finder*. It opens a submenu
  of seven colored options (Red … White). Clicking a color tags the
  session with it; clicking the color it *already* has (shown `checked`)
  clears it. Same item appears in the live row and inside a Bookmarks entry
  — both write the same sidecar.
* **See the tag** — a tagged session's row carries the colored circled
  letter immediately after the state circle, in both the live list and the
  Bookmarks submenu.

There is **no** new config knob (like Bookmarks). The feature is always
on; a session with no tag renders no glyph and the *Tags ▸* submenu
sits inert until used.

## How it works

Four parts, each mirroring the Bookmarks machinery (spec 0012) so there's
no new pattern to learn: a sidecar recording *what's tagged*, a set/clear
action that *writes* it, a reader + GC that *reads and prunes* it, and
render code that *shows* the tag glyph and the picker.

### The palette — one table, keyed by a stable string

A tag's stored value is a **color key** (`red`, `orange`, `yellow`,
`green`, `blue`, `purple`, `white`), never a hex or a localized name — so
the sidecar is i18n-independent and stable across releases. A single ordered
table in `core.py` maps key → circled letter + ANSI colour → localization key.
The composed `TAG_GLYPH` value is the letter wrapped in its ANSI escape, ready
to drop into an `ansi=true` line:

```python
_TAG_COLORS = (   # (key, circled letter, ANSI SGR params, i18n key)
    ("red",    "ⓡ", "38;5;196",        "tag.red"),
    ("orange", "ⓞ", "38;5;208",        "tag.orange"),
    ("yellow", "ⓨ", "38;5;220",        "tag.yellow"),
    ("green",  "ⓖ", "38;5;40",         "tag.green"),
    ("blue",   "ⓑ", "38;5;39",         "tag.blue"),
    ("purple", "ⓟ", "38;5;135",        "tag.purple"),
    ("white",  "ⓦ", "38;2;255;255;255", "tag.white"),
)
TAG_PALETTE = tuple(
    (key, f"\x1b[{sgr}m{letter}{_ANSI_RESET}", i18n) for key, letter, sgr, i18n in _TAG_COLORS
)
TAG_KEYS = frozenset(k for k, _, _ in TAG_PALETTE)
TAG_GLYPH = {k: g for k, g, _ in TAG_PALETTE}
```

**ANSI text colour, not `sfcolor`.** SwiftBar does **not** tint SF Symbols in
the dropdown at all: `sfcolor` (hex *and* named `system*`) renders every symbol
in the default monochrome — confirmed not just on our items but on the shipping
`sfcolor=systemRed`/`systemBlue` icons (Delete, Remind), which are gray in the
menu. ANSI *text* colour, however, renders fine (it's how the row labels are
coloured), so the tag colour lives in the letter's ANSI escape. Six colours use
256-colour (`38;5;N`); **white** uses truecolour pure white
(`38;2;255;255;255`) because both 256-cube white (`231`) and bright-white
(`97`) render gray in SwiftBar — full RGB bypasses the palette. Keys and
order are fixed here.

### The sidecar — `agent-state.tags`

A two-column TAB file, same shape and locking as `agent-state.bookmarks`
(`~/.claude/agent-state.tags`):

```
<session_id>\t<color_key>
```

One row per tagged session. New constants `TAGS_PATH` +
`_TAGS_LOCK_DIR` in `core.py` (next to `BOOKMARKS_PATH`, core.py:67 /
`_BOOKMARKS_LOCK_DIR`, core.py:191).

* **Reader** — `sidecars.read_tags() -> dict[str, str]`. Unlike
  `read_bookmarks`, the value is a **string** (color key), so it does
  **not** reuse `_parse_clicks` (which coerces col 2 to `int`). A small
  sibling parser `_parse_tags(raw)`: split on `\t`, require ≥2 columns,
  and **drop rows whose color key isn't in `TAG_KEYS`** (a corrupt or
  renamed color hides one tag, never crashes the menu). `{}` on
  `OSError`. Pure parser, tested in isolation.
* **GC (auto-prune)** — a tag whose transcript no longer exists is dead.
  Reuse the existing orphan pass exactly as Bookmarks does: the GC helper
  `_gc_two_col_sidecar` (sidecars.py:420) only inspects column 1 (the
  sid), so it works unchanged for a `sid\tcolor` file. Add a
  `_gc_two_col_sidecar(core.TAGS_PATH, stale, _tags_lock, "tags")` call
  next to the bookmarks one (sidecars.py:528), fed the same
  `set(tags) - _live_session_ids()` stale set. No tombstone — the tag
  vanishes with the session (covers *Delete…* and any external cleanup).

### The action — `bin/app/tag-set.sh`

Invoked from each color item as
`/bin/bash <script> <sid> <color_key|clear>` (same
executable-bit-independent `/bin/bash` invocation as `bookmark-set.sh`,
render.py:731). Semantics:

* `<color_key>` → **replace**: drop any existing row for `<sid>`, then
  append `<sid>\t<color_key>`. (Replace, not append-if-absent — changing
  color must overwrite; this differs from `bookmark-set.sh`'s
  preserve-date `on`.)
* `clear` → delete the `<sid>` row.

Both take the `mkdir`-based lock (`.lock.d`) like `bookmark-set.sh`, and
finish with `open swiftbar://refreshallplugins` so the menu redraws with
the new tag on the next tick. The awk is the same two-branch shape as
`bookmark-set.sh` (render.py template at bin/app/bookmark-set.sh:59), only
the "set" branch changes from *add-if-absent* to *replace*:

```bash
if [ "$MODE" = "clear" ]; then
    /usr/bin/awk -v sid="$SID" 'BEGIN{FS=OFS="\t"} $1==sid{next} {print}' ...
else
    # replace: drop old row for sid, append the new color
    /usr/bin/awk -v sid="$SID" -v new="$LINE" \
        'BEGIN{FS=OFS="\t"} $1==sid{next} {print} END{print new}' ...
fi
```

`$MODE` is validated against `clear` or membership in the seven keys;
anything else exits non-zero (defensive — render only ever passes valid
values).

### The session model — one field, threaded like `is_bookmarked`

`Session` gains `tag: Optional[str] = None` (the color key, or `None`).
Populated in `build_session` from the tags map the same way
`is_bookmarked` is threaded through `collect_sessions` → `build_session`
(spec 0012). No new parse — one dict lookup by sid.

### Rendering the tag — an inline ANSI letter in the row label

The tag glyph is the pre-composed `TAG_GLYPH` string (letter + ANSI colour)
inline in the label, right after the state circle. The row line already carries
`ansi=true`, so the colour renders:

```python
state_segment = f"{session.group.icon} " if show_state else ""
tag_segment = f"{core.TAG_GLYPH[session.tag]} " if session.tag else ""
label = f"{state_segment}{tag_segment}{session.title} · …"
```

Untagged rows are unchanged. Because Bookmarks reuse `_print_session_row`, a
tagged pinned session shows its letter in the Bookmarks submenu too, with zero
extra code. **No bookmark marker sits on the row** — see *Interaction with
Bookmarks*.

`show_state=False` (Bookmarks submenu): the state circle and the state row
colour are dropped and the right-label uses its uncoloured variant, so a pinned
session renders neutral — its live status is noise in the Bookmarks list.

### Rendering the picker — `Tags ▸` submenu after *Reveal in Finder*

A `_print_tags_picker(session, indent, bin_dir)` helper, called right after
the *Reveal in Finder* block in `_print_session_row`, threaded through the
same `indent`:

```
--Tags                            (parent; clean header, sfimage=tag)
  --ⓡ Red                         (----; colored letter leads the label, ansi=true)
  --ⓞ Orange
  --ⓨ Yellow
  --ⓖ Green    ✓ (if current)
  --ⓑ Blue
  --ⓟ Purple
  --ⓦ White
```

For each `(key, glyph, i18n_key)` in `TAG_PALETTE`, emit a child at
`{indent}----`, the coloured letter leading the label, **`ansi=true`** so the
colour renders:

```python
is_current = session.tag == key
print(
    f"{indent}----{glyph} {_t(i18n_key)} | "
    "shell=/bin/bash "
    f"param1={_swiftbar_quote(str(tag_set_script))} "
    f"param2={_swiftbar_quote(session.id)} "
    f"param3={'clear' if is_current else key} "     # toggle: clicking current clears
    f"checked={'true' if is_current else 'false'} "
    "terminal=false refresh=true ansi=true"
)
```

The `Tags` parent is a plain header (`sfimage=tag`, a monochrome section
marker); the current tag is already visible as the coloured letter on the row,
so it isn't repeated on the header.

Depth note: in the live list the picker options land at `----`; inside a
Bookmarks entry (row at `--`) they land at `------`. SwiftBar nests submenus
by increasing `--` depth, so this works; it's the deepest nesting in the menu
and is flagged for the manual GUI pass.

## i18n

Eight new keys, all 8 locales. English is source-of-truth; the existing
fallback chain (`requested → primary_subtag → en → key`) covers gaps.

* `menu.tags` — the *Tags ▸* parent ("Tags" / "Теги").
* `tag.red`, `tag.orange`, `tag.yellow`, `tag.green`, `tag.blue`,
  `tag.purple`, `tag.white` — the seven color names ("Красный",
  "Оранжевый", "Жёлтый", "Зелёный", "Синий", "Лиловый", "Белый").

## Icons

* **Row + picker color** — an ANSI-coloured circled letter (`ⓡⓞⓨⓖⓑⓟⓦ`),
  coloured via ANSI text colour, which SwiftBar *does* render in the dropdown
  (unlike `sfcolor` on SF Symbols).
* **Tags parent** — a monochrome `tag` SF Symbol as the section marker (all
  dropdown SF Symbols render monochrome here); no current-color indicator on
  it, since the row already shows the colour.

## Config

None. Always on; a session with no tag renders no glyph and the picker is
inert until used. (Same rationale as Bookmarks: this only *adds* an
inert-until-used surface, it doesn't change existing behavior, so no gate.)

## Interaction with Bookmarks (0012)

Orthogonal and complementary. Spec 0012 lists "Folders / tags / notes on
a bookmark" as out of scope — a *bookmark* stays `sid + date`. Tags are a
**separate** sidecar on the **session**, not on the bookmark. They meet only at
the shared `_print_session_row`: a tagged session shows its coloured letter
wherever that row renders, including inside a Bookmarks entry. No coupling
between the two sidecars; either can exist without the other.

**No bookmark marker on the row.** A bookmark icon would have to be an
`sfimage`, which SwiftBar always draws at the leading edge — *ahead* of the
state circle — and an inline emoji bookmark was rejected as ugly. So a pinned
session isn't marked in the live list at all; it's surfaced under the
*Bookmarks* submenu (whose header + the per-row *Bookmark* toggle carry the
`bookmark.fill` icon). The row shows only state (live list) and tag colour.

## Cost

One extra `read_tags()` per tick (a single small TSV, `{}` when empty) and
one dict lookup per rendered session — the same profile as the bookmarks
/ forget / clicks maps already read every tick. No transcript parsing is
added (the tag is a pointer; the row is already built). Within the
project's "no expensive parsing on the 5 s tick" rule.

## Acceptance

1. `read_tags` round-trips a valid `sid\tcolor` file; drops rows with `<2`
   columns and rows whose color key ∉ `TAG_KEYS`; returns `{}` on a
   missing/unreadable file.
2. `bash -n bin/app/tag-set.sh` exits 0. A color arg **replaces** any
   existing row for the sid (a second, different color overwrites — the
   file never holds two rows for one sid); `clear` removes the row;
   an invalid mode exits non-zero; concurrent writers serialize on
   `.lock.d`.
3. Auto-prune: a tagged `sid` with no `~/.claude/projects/*/<sid>.jsonl`
   is dropped by the shared orphan pass
   (`set(tags) - _live_session_ids()` → `_gc_two_col_sidecar`) and never
   rendered.
4. `_print_session_row` for an **untagged** session shows no tag glyph and no
   bookmark icon (`sfimage=bookmark.fill` never appears on a row). A tagged
   session inserts the colour's `TAG_GLYPH` letter after the state circle on an
   `ansi=true` line; nothing else changes.
5. The *Tags ▸* submenu emits seven options in `TAG_PALETTE` order, each with
   its coloured letter leading the label on an `ansi=true` line; the option
   matching `session.tag` is `checked=true` and passes `param3=clear`
   (toggle-off), every other passes `param3=<its key>`; an untagged session has
   no checked option and no colour on the parent.
6. `Session.tag` is populated from the tags map by sid (present → key,
   absent → `None`), threaded through `collect_sessions`/`build_session`
   exactly like `is_bookmarked`.
7. The tag letter renders in a **Bookmarks** entry too: a session that is both
   tagged and pinned shows its letter on its row at `indent="--"` with the
   picker options at `------`, no bookmark-specific code — and, because
   `show_state=False` there, no state circle/colour.
8. Every new i18n key (`menu.tags` + seven `tag.*`) resolves in all 8
   locales (no key falls through to the literal).
9. Full `unittest` suite green (including the above).
10. **Manual GUI required before release** (SwiftBar clicks, checkmarks, ANSI
    colour, and nesting aren't scriptable): open a session's *Tags ▸* → the
    seven options show **distinct colours** (verify orange and white in
    particular — orange needs 256-colour, white needs truecolour); pick a
    color → the row shows that coloured letter after the state circle; re-pick
    → it clears; pick another → it replaces; the current shows `checked`; a
    pinned session shows **no** bookmark icon in the live list but appears under
    *Bookmarks* (neutral, no state) with its tag letter.

## Out of scope

* **Multiple tags per session.** Locked to one color (product decision 1).
  Revisit only if the single-color model proves too coarse.
* **Renaming tags / custom colors / custom labels.** Finder's fixed seven,
  fixed names. No user-defined palette.
* **A "Tagged" top-level submenu** (grouping/filtering all tagged sessions
  the way Bookmarks groups pinned ones). Not asked for; tags are a per-row
  marker, not a collection view. Revisit if it's wanted later — it would
  reuse the same `read_tags` + row renderer.
* **Syncing tags across machines** — the sidecar is local, like every
  other `agent-state.*` file.
* **Config knob** — always on, inert when unused (see *Config*).
